# 전세한눈 v0.1 다분야 관점 검토

2026-10-22. 다음은 역할 관점을 적용한 설계 검토이며 실제 전문가 회의·법률 검수 완료를 의미하지 않습니다.

| 관점 | 우려·반론 | 반영한 결정 |
|---|---|---|
| 기획자 | 조회 화면만으로 실제 확인 행동이 이어지지 않음 | 집별 프로젝트와 다음 확인 항목 연결 |
| UX 설계자 | 처음부터 법률 항목이 많아 혼란 | 현재 계약 단계와 단계별 확인 방법 우선 |
| 디자이너 | 초록 안전 점수가 과도한 신뢰 유발 | 안전 점수 금지, 근거 기록·미확인·불일치 세 수치 분리 |
| 공인중개사 | 서류 확인 없이 사용자 체크만 완료 | 확인 메모·근거 서류 연결, 요청 문구 제공 |
| 변호사 | 특약·체크리스트가 계약 안전을 보장하지 않음 | 자동 안전 인증·계약 해제 지시 없음, 상담 경로 제공 |
| 법무사 | 등기 과거 이력과 현재 권리 혼동 | 원문 열람, 말소 여부·잔금일 재확인 가이드 |
| 지적과 공무원 관점 | 건축 용도·지적·등기 담당 기관 혼동 | 등기는 인터넷등기소, 건축 사항은 관할 건축 담당 부서로 구분 |
| 임차인 | 화면 닫으면 파일·점검이 없어짐 | IndexedDB 트랜잭션 저장, 재접속 복원, 원본 포함 백업 |
| 임대인 | 이름만으로 사기 여부 단정·개인정보 확산 | 공개 명단·사기범 라벨 없음. 확인 요청과 자료 대조 중심 |

## 범위
브라우저 로컬 저장형 정적 MVP. 회원 로그인, 서버 동기화, OCR, 실거래/등기/세금 자동 조회, 공식 보증기관 연계, 푸시 알림은 미구현입니다. 미구현 기능을 수행한 것처럼 표시하지 않습니다.

## 검수 시나리오
신규 집 → 메모와 파일 등록 → 점검 근거 연결 → 재접속 → 파일 재열람 → 이전 상태 비교 → 백업 → 별도 신규 프로젝트로 복원.
확인 근거 없음·오래된 잔금 등기·빈 금액·다가구 선순위 미확인·브라우저 저장 실패·백업 악성 HTML도 별도로 검증합니다.

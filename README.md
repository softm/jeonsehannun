# 전세한눈

전세계약의 위험요인과 미확인 정보를 살펴보고, 계약 단계마다 필요한 확인 행동을 안내하는 웹앱입니다.

> **현재 상태:** 저장소 초기 구성 및 요구사항 정리 단계입니다. 웹앱 구현·배포 전이며, 아래 기능은 개발 계획입니다.

## 제품 목표

가계약금 송금 전부터 계약서 작성, 잔금 지급까지 사용자가 확인한 근거와 남은 과제를 한곳에서 관리하도록 돕습니다.
점검 결과는 확인한 자료의 범위와 기준일을 함께 보여주며, 계약의 안전을 보장하는 인증으로 표시하지 않습니다.

## 세 가지 실전 가이드

| 단계 | 확인할 내용 | 화면에서 안내할 행동 |
|---|---|---|
| 가계약금 보내기 전 | 정확한 주소·동호수, 거래 상대방, 보증금 수준, 가계약 조건 | 미확인 항목과 송금 전에 요청할 자료 정리 |
| 계약서 작성 전 | 최신 등기사항, 건축물 정보, 임대 권한, 선순위 보증금, 세금 관련 증빙, 계약 조건 | 문서 사이의 불일치 확인 및 추가 확인·상담 과제 제시 |
| 잔금 보내기 전 | 이전 점검 이후의 권리 변동, 계약 조건 이행, 지급 상대방, 입주·신고·보증 준비 | 재확인할 자료와 완료 여부를 점검하고 후속 일정 관리 |

각 항목에서 확인 경로, 요청할 자료, 서류에서 볼 부분, 결과에 따른 다음 행동을 안내합니다.
이미 계약한 후의 해제나 지급 보류는 계약별 검토가 필요하므로 계약 전 선택 기준과 구분합니다.

## 판단 원칙

- **미확인을 안전으로 취급하지 않습니다.** 자료 없음, 조회 실패, 오래된 자료를 구분합니다.
- 위험요인마다 근거 문서·출처·확인 시각·다음 행동을 함께 표시합니다.
- 문서의 자동 추출 결과는 원문과 대조할 수 있도록 하고, 사용자의 확인·수정 이력을 남깁니다.
- 실거래가와 주변 시세는 비교 자료로 사용하며, 특정 주택의 회수 가능 금액을 확정하지 않습니다.
- 신탁·다가구·대리계약 등은 추가 증빙과 권한 확인을 별도 단계로 안내합니다.
- 보증은 **가입 가능성 사전검토 → 신청 → 심사 → 보증서 발급** 상태를 구분합니다.
- 공식 조회 연결과 앱 내부의 자동 조회를 명확히 구분하며, 실제 연계가 확인된 기능부터 제공합니다.
- 수집 주기, 마지막 수집 성공 시각, 원본 데이터 기준일과 오류·누락 상태를 구분해 표시합니다.

## 사용자별 프로젝트와 기록 보관 계획

- 검토할 집마다 프로젝트를 만들고 주소, 보증금, 계약 단계, 일정 등을 관리합니다.
- 원본 서류, 확인 결과, 메모, 변경 이력을 프로젝트에 연결해 영속적으로 보관합니다.
- 화면을 닫거나 다시 로그인해도 저장된 프로젝트와 작업 내용을 이어서 확인할 수 있도록 설계합니다.
- 저장 중·저장 완료·저장 실패 상태를 표시하고, 실패한 작업은 재시도할 수 있도록 합니다.
- 계약 서류는 사용자별 접근 권한을 적용하고, 공개 저장소나 공개 배포 파일에 포함하지 않습니다.

## 첫 개발 범위

- [ ] 프로젝트 생성·목록·다시 열기와 저장 상태 표시
- [ ] 계약 단계별 확인 목록 및 미확인 항목 관리
- [ ] 원본 서류 업로드·열람과 점검 이력 보관
- [ ] 공식 확인 경로 안내 및 보증 진행 상태 관리
- [ ] 계약 전 자료와 잔금 전 자료의 변경 비교
- [ ] 데이터 기준일·수집 시각·실패 상태 안내

## 초기 검증 기준

- 다시 로그인해도 프로젝트·원본 서류·점검 이력이 복원됩니다.
- 누락된 선순위 보증금은 0원으로 계산하지 않습니다.
- 일부 페이지만 제출되거나 문서가 불명확하면 추가 확인을 요청합니다.
- 현재 권리와 말소된 이력을 구분하고, 불확실한 추출은 원문 대조를 요구합니다.
- 다른 주소나 호실의 자료가 섞이면 확인 완료로 처리하지 않습니다.
- 보증 사전검토 결과를 보증서 발급 완료로 표시하지 않습니다.

## 저장소 범위

이 저장소에는 웹앱 소스와 공개 가능한 제품·개발 문서를 관리합니다.
실제 계약서, 신분증, 개인별 등기 자료, 인증 비밀값은 커밋하지 않습니다.
기술 스택과 배포 환경은 구현 단계에서 확정합니다.
